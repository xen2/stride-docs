# Stride 4.5 release notes

> [!NOTE]
> Stride 4.5 is in development. These release notes are in progress: they describe the 4.5 betas and change with each one.

## Highlights

Here are a few of the stand-out changes:

### New in SDSL

* **Modules:** a class that holds functions, constants or state shared by the whole effect is declared `module X` and used with `import X;`. A module exists once per effect, also when the shaders that import it are in several composition slots. See [Shaders and modules](../manual/graphics/effects-and-shaders/shading-language/shaders-and-modules.md).
* **Partial structs:** a module declares `partial struct X`, and plugins add fields with `extend struct X`. Data passes through parameters instead of streams, so the code runs in any stage. See [Partial structs](../manual/graphics/effects-and-shaders/shading-language/automatic-shader-stage-input-output.md#partial-structs).
* **`[Root]`:** marks a shader that is only mixed at the root of an effect (post effects, compute shaders), so the module rules don't apply to it. See [Root-only shaders](../manual/graphics/effects-and-shaders/shading-language/shaders-and-modules.md#root-only-shaders).
* **`[Pure]`:** marks a module with functions and constants only; the compiler checks it, so the module can run in any stage. See [Pure modules](../manual/graphics/effects-and-shaders/shading-language/shaders-and-modules.md#pure-modules).
* **Push constants:** a `[PushConstant] cbuffer` holds a few small values that C# sets just before a draw or a dispatch with `CommandList.SetPushConstants`: push constants on Vulkan, root constants on Direct3D 12, a constant buffer on Direct3D 11. See [Push constants](../manual/graphics/effects-and-shaders/shading-language/shaders-and-modules.md#push-constants).
* **Checks when a shader compiles:** mistakes in overrides, `base` calls, generic values and module rules are reported when the shader class compiles, with the fix, not only when an effect uses it. Most of them are warnings for now. See [Inheritance and overrides](../manual/graphics/effects-and-shaders/shading-language/shader-classes-mixins-and-inheritance.md).

## Breaking changes

* **Custom shaders (SDSL):** the `stage` modifier is now written `module`, classes that hold only shared code or state are now declared `module X` and used with `import X;`, and using a member of a shader by name (`X.Member`) without inheriting it is now an error. The project upgrade rewrites your `.sdsl` files for you; for what it changes and what you may need to fix by hand, see [Upgrading shaders from 4.4](upgrading-shaders-4.5.md).
* **Packages with shaders:** a package built for Stride 4.4 whose shaders use `stage` doesn't work in 4.5 ([SDSL0045](../diagnostics/SDSL0045.md)). It needs a new version, made with the project upgrade.
* **Removed engine shaders:** the five `ComputeColorTexture...` shaders that took the texture as a generic parameter are removed: no effect that used them could compile since Stride 4.4. See [Removed engine shaders](upgrading-shaders-4.5.md#removed-engine-shaders).
