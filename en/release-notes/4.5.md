# Stride 4.5 release notes

> [!NOTE]
> Stride 4.5 is in development. These release notes are in progress: they describe the 4.5 betas and change with each one.

## Highlights

Here are a few of the stand-out changes:

### New in SDSL

* **Modules:** a class that holds functions, constants or state shared by the whole effect is declared `module X` and used with `import X;`. A module exists once per effect, also when the shaders that import it are in several composition slots. See [Shaders and modules](../manual/graphics/effects-and-shaders/shading-language/shaders-and-modules.md).
* **Partial structs:** a module declares `partial struct X`, and plugins add fields with `extend struct X`. Data passes through parameters instead of streams, so the code runs in any stage. See [Partial structs](../manual/graphics/effects-and-shaders/shading-language/automatic-shader-stage-input-output.md#partial-structs).
* **Namespaces:** shaders and effects have real namespaces, as C# types do, and `[Replaces]` replaces a shader for the whole game. See [Namespaces](../manual/graphics/effects-and-shaders/shading-language/namespaces.md).
* **`[Root]`:** marks a shader that is only mixed at the root of an effect (post effects, compute shaders), so the module rules don't apply to it. See [Root-only shaders](../manual/graphics/effects-and-shaders/shading-language/shaders-and-modules.md#root-only-shaders).
* **`[Pure]`:** marks a module with functions and constants only; the compiler checks it, so the module can run in any stage. See [Pure modules](../manual/graphics/effects-and-shaders/shading-language/shaders-and-modules.md#pure-modules).
* **Extension points:** a method says how its overrides combine (`pipeline`, `around` or `replace`) and in which phases, so the order of the mixins no longer decides what runs first. A class says where it runs with `[Phase]` and `[MixinOrder]`, and an effect changes that for itself with `extend shader` blocks. See [Extension points](../manual/graphics/effects-and-shaders/shading-language/extension-points.md).
* **`extend effect`:** a plugin or a game adds to an effect of another project, such as an engine effect, without copying it. See [Effects (SDFX)](../manual/graphics/effects-and-shaders/effect-language.md).
* **Push constants:** a `[PushConstant] cbuffer` holds a few small values that C# sets just before a draw or a dispatch with `CommandList.SetPushConstants`: push constants on Vulkan, root constants on Direct3D 12, a constant buffer on Direct3D 11. See [Push constants](../manual/graphics/effects-and-shaders/shading-language/shaders-and-modules.md#push-constants).
* **Checks when a shader compiles:** mistakes in overrides, `base` calls, generic values and module rules are errors when the shader class compiles, with the fix, not only when an effect uses it. See [Inheritance and overrides](../manual/graphics/effects-and-shaders/shading-language/shader-classes-mixins-and-inheritance.md).

## Breaking changes

* **Custom shaders (SDSL):** the `stage` modifier is now written `module`, classes that hold only shared code or state are now declared `module X` and used with `import X;`, and using a member of a shader by name (`X.Member`) without inheriting it is now an error. The project upgrade rewrites your `.sdsl` files for you; for what it changes and what you may need to fix by hand, see [Upgrading shaders from 4.4](upgrading-shaders-4.5.md).
* **Mistakes in shaders are errors:** what Stride 4.4 let through, or reported as a warning, is an error when it is a mistake in the shader. See [Mistakes are errors](upgrading-shaders-4.5.md#mistakes-are-errors).
* **Overrides of `module` methods:** overriding a `module` method that is not an extension point is an error ([SDSL0246](../diagnostics/SDSL0246.md)), and engine classes now run in their phase wherever they are mixed, so a class mixed before the engine may now run after it. The project upgrade adds the kinds your project needs. See [Extension points](upgrading-shaders-4.5.md#extension-points).
* **Packages with shaders:** a package built for Stride 4.4 whose shaders use `stage` doesn't work in 4.5 ([SDSL0045](../diagnostics/SDSL0045.md)). It needs a new version, made with the project upgrade.
* **Names of shaders and effects:** C# strings and stored data take the full name (`Stride.Rendering.ComputeColor`), or the generated `XxxKeys.ShaderName` and `XxxKeys.EffectName`. The name of a shader member's key is the full name of the class plus the member. A shader or an effect with no namespace keeps its name. The project upgrade rewrites literals and assets; see [Names in your C#](upgrading-shaders-4.5.md#names-in-your-c).
* **Macros belong to the effect:** `ShaderMixinSource` no longer has `Macros` or `AddMacro`; the effect compiler takes an `EffectSource`, which holds the root of the tree and the macros of the whole effect. See [Macros belong to the effect](upgrading-shaders-4.5.md#macros-belong-to-the-effect).
* **Effect logs:** the project upgrade deletes the `.sdeffectlog` files of your project, recorded on an older version. Record them again; see [Effect logs](upgrading-shaders-4.5.md#effect-logs).
* **Removed engine shaders:** the five `ComputeColorTexture...` shaders that took the texture as a generic parameter (no effect that used them could compile since Stride 4.4), and `BackgroundVelocity`, `ComputeColorScaler`, `FlattenLayers`, `GBuffer`, `SelectedSpriteShader`, `ShadingColor`, `SwapUV`, `TransformationMatrix`, `TransformationWVP`, `TransformationZero` and the effects `BackgroundVelocityEffect` and `SelectedSprite`, with their key classes, because nothing uses them. See [Removed engine shaders](upgrading-shaders-4.5.md#removed-engine-shaders).
