# Stride 4.5 release notes

> [!NOTE]
> Stride 4.5 is in development. These release notes are in progress: they describe the 4.5 betas and change with each one.

## Highlights

Here are a few of the stand-out changes:

### New in SDSL

* **Partial structs:** a module declares `partial struct X`, and plugins add fields with `extend struct X`. Data passes through parameters instead of streams, so the code runs in any stage. See [Partial structs](../manual/graphics/effects-and-shaders/shading-language/automatic-shader-stage-input-output.md#partial-structs).
* **`[Root]`:** marks a shader that is only mixed at the root of an effect (post effects, compute shaders), so the module rules don't apply to it. See [Root-only shaders](../manual/graphics/effects-and-shaders/shading-language/shaders-and-modules.md#root-only-shaders).
* **`[Pure]`:** marks a module with functions and constants only; the compiler checks it, so the module can run in any stage. See [Pure modules](../manual/graphics/effects-and-shaders/shading-language/shaders-and-modules.md#pure-modules).
* **Checks when a shader compiles:** mistakes in overrides, `base` calls, generic values and module rules are reported when the shader class compiles, with the fix, not only when an effect uses it. See [Inheritance and overrides](../manual/graphics/effects-and-shaders/shading-language/shader-classes-mixins-and-inheritance.md).

## Breaking changes

* **Custom shaders (SDSL):** the `stage` modifier is now written `module`, classes that hold only shared code or state are now declared `module X` and used with `import X;`, and using a member of a shader by name (`X.Member`) without inheriting it is now an error. The project upgrade rewrites your `.sdsl` files for you; for what it changes and what you may need to fix by hand, see [Upgrading shaders from 4.4](upgrading-shaders-4.5.md).
