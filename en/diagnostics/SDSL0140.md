# Diagnostics Error SDSL0140

> {0} is in phase {1} of {2} and {3}. A step before the phase of the default body ({4}) calls base last, a step after it calls base first.

Reported by the shader compiler since Stride 4.5.

## Explanation

The steps of a `[Pipeline]` [extension point](../manual/graphics/effects-and-shaders/shading-language/extension-points.md) run in phase order. A step runs where its `base` call puts it, so the place of `base` has to agree with the phase. A step before the phase of the first definition calls `base` last. A step after it calls `base` first. In the phase of the first definition, either one works.

A `base` call in the middle of the body, inside an `if`, or twice, has no single place in the order.

An override without `[Phase]` isn't checked: it is outside every phase, and it can call `base` anywhere.

## Example

The following example generates SDSL0140: `base` runs the earlier phases after this step.

```cs
module MyModule
{
    stream float Value;

    [Pipeline(Default, Late)]
    void Run() {}
};

module MyStep
{
    import MyModule;

    [Phase(Late)]
    override void Run()
    {
        streams.Value = 1;
        base.Run();
    }
};
```

The following example doesn't generate SDSL0140:

```cs
module MyStep
{
    import MyModule;

    [Phase(Late)]
    override void Run()
    {
        base.Run();
        streams.Value = 1;
    }
};
```

## Solution

Move the `base` call, or pick the phase where the step really runs. For a `base` call that can't move, remove `[Phase]`.
