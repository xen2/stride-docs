# Diagnostics Error SDSL0151

> the block {0} is inside the composition {1}. A block belongs to the whole effect: write it at the top level of the effect.

Reported when an effect is generated, since Stride 4.5.

## Explanation

A [block](../manual/graphics/effects-and-shaders/effect-language.md#blocks) is about the `module` methods of an effect, and these go to the root of the effect, wherever a class is mixed. A block inside a composition would change what runs in the whole effect, not only in that composition.

Blocks therefore work at the top level of an effect, and in an effect you mix with `mixin`. In an effect you mix with `mixin compose`, a block is this error.

## Example

The following example generates SDSL0151:

```cs
effect MyLayer
{
    extend shader ShaderBase { [Unbind(Phases = { Shade })] PSMain; }
    mixin MyLayerShader;
};

effect MyEffect
{
    mixin MyBase;
    mixin compose Layer = MyLayer;
};
```

## Solution

Write the block at the top level of the effect that has the composition:

```cs
effect MyLayer
{
    mixin MyLayerShader;
};

effect MyEffect
{
    extend shader ShaderBase { [Unbind(Phases = { Shade })] PSMain; }
    mixin MyBase;
    mixin compose Layer = MyLayer;
};
```

If `MyLayer` is also an effect of its own, and needs the block then, move what the composition uses to a separate effect:

```cs
effect MyLayerPart
{
    mixin MyLayerShader;
};

effect MyLayer
{
    extend shader ShaderBase { [Unbind(Phases = { Shade })] PSMain; }
    mixin MyLayerPart;
};

effect MyEffect
{
    mixin MyBase;
    mixin compose Layer = MyLayerPart;
};
```

From C#, blocks go on an @'Stride.Shaders.EffectSource', next to the root of the tree:

```cs
var effect = new EffectSource(root);
effect.UnbindPhases("Stride.Rendering.ShaderBase", "PSMain", "Shade");
```
