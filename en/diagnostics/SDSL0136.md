# Diagnostics Error SDSL0136

> {0}.{1} doesn't call next, so {2} never run in this effect. Write replaces {3}, or call next.

Reported by the shader compiler since Stride 4.5, for an effect built by the asset compiler: the entries of an effect log. In a mix built at run time, the same text goes to the log as information, because replacing engine code is often the point there.

## Explanation

An `extend` of an [extension point](../manual/graphics/effects-and-shaders/shading-language/extension-points.md) doesn't call `next`, so what comes before it in the chain doesn't run. In an effect built by the asset compiler, `extend` has to say it. The same override written with `override` is [SDSL0216](SDSL0216.md).

Replacing the first definition doesn't count: that is what an override is for.

## Example

The following example generates SDSL0136 when `MyTint` and `MyFixedColor` are mixed in one effect:

```cs
module MyColor
{
    [Around(Outer, Inner)]
    float4 Color() { return 0; }
};

module MyTint
{
    import MyColor;

    extend MyColor.Color in Inner { return next() * 2; }
};

module MyFixedColor
{
    import MyColor;

    extend MyColor.Color in Outer { return 1; }
};
```

The following example doesn't generate SDSL0136:

```cs
module MyFixedColor
{
    import MyColor;

    extend MyColor.Color in Outer replaces MyTint { return 1; }
};
```

## Solution

Call `next`, or write `replaces` with the classes or the phase that this one stands in for.
