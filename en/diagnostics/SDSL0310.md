# Diagnostics Error SDSL0310

> extend effect {0}: no effect has this name. Check the name and the namespace, and reference the project that declares the effect.

Reported when your project builds since Stride 4.5, and when the effect is asked for if the assembly that declares it isn't loaded.

## Explanation

[`extend effect`](../manual/graphics/effects-and-shaders/effect-language.md#add-to-an-effect-from-another-project) adds to an effect of another project. No project that this one references declares an effect with this full name. Nothing would ever ask for an effect that doesn't exist, so without this error the layer would silently do nothing.

The full name is the namespace of the `extend effect` followed by its name, so it has to be written in the namespace of the effect. A `using` doesn't change it.

The build looks for the effect through the `EffectName` constant of its key class, which the generator writes for an effect in a `.sdfx` file. If the effect is a builder written in C#, give it a public class named `{Name}Keys`, in its namespace, with `public const string EffectName = "{full name}";`.

## Example

The following example generates SDSL0310, because `StrideForwardShadingEffect` is in the namespace `Stride.Rendering`:

```cs
namespace MyGame
{
    extend effect StrideForwardShadingEffect
    {
        mixin MyFogShader;
    }
}
```

## Solution

Write the `extend effect` in the namespace of the effect, and fix the name if it is misspelled:

```cs
namespace Stride.Rendering
{
    extend effect StrideForwardShadingEffect
    {
        mixin MyFogShader;
    }
}
```

If the effect comes from a package, reference that package from the project.
