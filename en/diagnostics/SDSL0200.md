# Diagnostics Warning SDSL0200

> {0}.{1}() is marked 'override', but no inherited class declares {1}: it starts a new method, and calls made through a parent never reach it. Inherit the class that declares {1}, or remove 'override'.

Reported by the shader compiler since Stride 4.5.

## Explanation

`override` replaces a method that a parent class (a shader you inherit, or a module you inherit or `import`) declares. When no parent declares a method of that name, the method is a new method: code that calls the method through the parent, or through a composition of the parent's type, never reaches it.

Before Stride 4.5 this was silent. A common case is a class used as the value of a `compose` slot that doesn't inherit the type of the slot.

## Example

The following example generates SDSL0200 on `Compute`:

```cs
shader ColorProvider
{
    abstract float4 Compute();
};

// Used as the value of "compose ColorProvider color;", but doesn't inherit ColorProvider
shader RedColor
{
    override float4 Compute()
    {
        return float4(1, 0, 0, 1);
    }
};
```

The following example doesn't generate SDSL0200:

```cs
shader RedColor : ColorProvider
{
    override float4 Compute()
    {
        return float4(1, 0, 0, 1);
    }
};
```

## Solution

Inherit the class that declares the method, or remove `override` if the method is really a new one.

To make this warning fail the build (it will be an error in a later release), set the MSBuild property `StrideShaderWarningsAsErrors` to `true` in your project.
