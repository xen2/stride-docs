# Diagnostics Warning SDSL0220

> {0} on {1} is ignored: Stride lays out cbuffers and binds resources itself. Remove it.

Reported by the shader compiler since Stride 4.5.

## Explanation

In HLSL, `: register(...)` places a variable in a given register, and `: packoffset(...)` places a cbuffer member at a given offset. Stride lays out the cbuffers and binds the resources of an effect itself, and the engine reads the layout back from the compiled shader, so the compiler drops these qualifiers. Your shader works the same, but at the offsets and registers Stride chooses.

## Example

The following example generates SDSL0220:

```cs
shader MySharpen : ComputeColor
{
    float2 PixelSize : register(c1);

    override float4 Compute()
    {
        return float4(PixelSize, 0, 1);
    }
};
```

The following example doesn't generate SDSL0220:

```cs
shader MySharpen : ComputeColor
{
    float2 PixelSize;

    override float4 Compute()
    {
        return float4(PixelSize, 0, 1);
    }
};
```

## Solution

Remove the `register(...)` or `packoffset(...)` qualifier. To set the value from C#, use the parameter key generated for the member.

To make this warning fail the build, set the MSBuild property `StrideShaderWarningsAsErrors` to `true` in your project.
