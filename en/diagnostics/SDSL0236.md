# Diagnostics Warning SDSL0236

> the value of composition {0} is ignored: a composition gets its shader from the effect, not from a value. Remove '= {1}'.

Reported by the shader compiler since Stride 4.5.

## Explanation

A composition (`compose`) holds a shader that the effect chooses (`mixin compose Name = ...` in an `.sdfx` file, or a key set from C#). A value written after its name, such as `compose ComputeFloat Distance = 0.1f;`, is never used: Stride 4.3 ignored it silently, and since Stride 4.5 the shader compiles with this warning (in Stride 4.4 the shader failed to compile).

The value stays in the parsed shader, so a tool that reads the source can still see it, but the engine doesn't use it as a default. A tool that needs a default reads its own attribute instead, for example `[Default(...)]` in vvvv gamma.

## Example

The following example generates SDSL0236:

```cs
shader MyFade : ComputeColor
{
    compose ComputeFloat Opacity = 1;

    override float4 Compute()
    {
        return float4(1, 1, 1, Opacity.Compute());
    }
};
```

The following example doesn't generate SDSL0236:

```cs
shader MyFade : ComputeColor
{
    compose ComputeFloat Opacity;

    override float4 Compute()
    {
        return float4(1, 1, 1, Opacity.Compute());
    }
};
```

## Solution

Remove `= value`. The project upgrade to Stride 4.5 removes it for you. To give the composition a default, set it in the effect (`mixin compose Opacity = ...`) or from the tool that builds the effect.

To make this warning fail the build, set the MSBuild property `StrideShaderWarningsAsErrors` to `true` in your project.
