# Diagnostics Error SDSL0138

> the order of {0} can't be followed: {1}.

Reported by the shader compiler since Stride 4.5.

## Explanation

The orders written on the overrides of an [extension point](../manual/graphics/effects-and-shaders/shading-language/extension-points.md) contradict each other:

- the orders go in a circle, through `[MixinOrder]` of classes and the blocks of the effect. The message gives each order and where it is written;
- two orders of one level say opposite things, for example two blocks of one effect: neither is further out, so neither replaces the other;
- `[MixinOrder]` names a class of another phase, or an override without a phase. The phases already order them, and a phase always wins;
- phases added next to each other contradict, for example two classes that add one phase with neighbours that disagree;
- two blocks of one level put a class in two phases;
- two overrides drop each other with `[Drops]`.

## Example

The following example generates SDSL0138:

```cs
module MyPipeline
{
    [Phases(Steps)]
    pipeline void Run() {}
};

module StepA
{
    import MyPipeline;

    [Phase(Steps)]
    [MixinOrder(After = StepB)]
    override void Run() { base.Run(); }
};

module StepB
{
    import MyPipeline;

    [Phase(Steps)]
    [MixinOrder(After = StepA)]
    override void Run() { base.Run(); }
};
```

The following example doesn't generate SDSL0138:

```cs
module StepA
{
    import MyPipeline;

    [Phase(Steps)]
    override void Run() { base.Run(); }
};
```

## Solution

Remove one of the orders, or move the overrides to phases that agree with them. To change an order you don't own, write the opposite order in a block of the effect: an outer level replaces the opposite order of an inner one.
