# Diagnostics Warning SDSL0204

> {0}.{1}() is module code and reads {2}, an instance member of {3}. If {0} is used in a composition, each instance has its own {2}. Mark {2} 'module', or mark {0} [Root] if it is only mixed at the root of an effect.

Reported by the shader compiler since Stride 4.5.

## Explanation

Module code (a `module` method, or a method of a module) exists once per effect. An instance member (a member without `module`) has one value per instance of the shader: when a material uses the shader in two slots, each slot has its own value.

So module code can't read an instance member: it can't know which instance to read. When the shader is used in a composition, the effect fails to build. When the shader is mixed at the root of an effect, it is the only instance, and the code works.

The compiler checks this when the class compiles, unless the class is root-only (see [SDSL0119](SDSL0119.md)).

## Example

The following example generates SDSL0204 on `Speed`:

```cs
shader MyRippleColor : ComputeColor
{
    [Color] float4 Color;
    float Speed;

    module float Phase()
    {
        return Global.Time * Speed;
    }

    override float4 Compute()
    {
        return Color * (0.5 + 0.5 * sin(Phase()));
    }
};
```

The following example doesn't generate SDSL0204:

```cs
shader MyRippleColor : ComputeColor
{
    [Color] float4 Color;
    module float Speed;

    module float Phase()
    {
        return Global.Time * Speed;
    }

    override float4 Compute()
    {
        return Color * (0.5 + 0.5 * sin(Phase()));
    }
};
```

## Solution

Choose one:

- Mark the member `module` when it has one value for the whole effect.
- Remove `module` from the method when it should use the values of each instance.
- Mark the shader `[Root]` when it is only mixed at the root of an effect (a post effect, an effect feature).

To make this warning fail the build (it will be an error in a later release), set the MSBuild property `StrideShaderWarningsAsErrors` to `true` in your project.
