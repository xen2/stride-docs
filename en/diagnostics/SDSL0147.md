# Diagnostics Error SDSL0147

> #{0} reads {1}, a generic parameter of {2}. A condition runs before generics get their value, so {1} would count as undefined here. Use a plain if, or a separate class for each value.

Reported when your project builds, since Stride 4.5.

## Explanation

`#if`, `#ifdef`, `#ifndef`, `#elif` and `defined()` run in the preprocessor, before the compiler knows the value of a generic parameter. A name that is no macro counts as undefined in a condition, so the condition would take the same branch for every value, and the shader would silently be wrong.

These conditions stay valid, as in HLSL: a name nothing declares, a `static const`, and a name that is a macro at that point.

## Example

The following example generates SDSL0147:

```cs
shader MyBlur<int Samples>
{
#if Samples == 3
    float Weight() { return 0.5f; }
#else
    float Weight() { return 0.25f; }
#endif
};
```

The following example doesn't generate SDSL0147:

```cs
shader MyBlur<int Samples>
{
    float Weight()
    {
        if (Samples == 3)
            return 0.5f;
        return 0.25f;
    }
};
```

## Solution

Use a plain `if`, which sees the value. If the branches declare different members, write a separate class for each value.
