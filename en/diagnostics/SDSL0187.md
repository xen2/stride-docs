# Diagnostics Error SDSL0187

> {0} on a float is not supported: on Vulkan it needs float atomics, which Stride doesn't enable. Store the float's bits in an int or uint (asuint, asfloat) and update it with InterlockedCompareExchange.

Reported when your project builds, since Stride 4.5.

## Explanation

HLSL has atomic operations on `float` values: `InterlockedExchange` on a `float`, `InterlockedCompareExchangeFloatBitwise`, `InterlockedCompareStoreFloatBitwise`, and the `RWByteAddressBuffer` methods `InterlockedExchangeFloat`, `InterlockedCompareExchangeFloatBitwise` and `InterlockedCompareStoreFloatBitwise`. On Vulkan they need a device feature (float atomics) that Stride doesn't enable, so Stride doesn't support them.

## Example

The following example generates SDSL0187:

```cs
shader LastValue : ComputeShaderBase
{
    RWStructuredBuffer<float> Values;

    override void Compute()
    {
        float previous;
        InterlockedExchange(Values[0], 1.5, previous);
    }
};
```

The following example doesn't generate SDSL0187:

```cs
shader LastValue : ComputeShaderBase
{
    RWStructuredBuffer<uint> Values;

    override void Compute()
    {
        uint previousBits;
        InterlockedExchange(Values[0], asuint(1.5), previousBits);
        float previous = asfloat(previousBits);
    }
};
```

## Solution

Keep the float's bits in a `uint` (or `int`) buffer: write them with `asuint`, read them with `asfloat`. `InterlockedExchange` and `InterlockedCompareExchange` on the bits do what the float versions do.
