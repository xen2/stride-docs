# Diagnostics Error SDSL0137

> {0} and {1} are both in phase {2} of {3} and {4}, and nothing orders them. Add [After({0})] to {1}, or [After({1})] to {0}.

Reported by the shader compiler since Stride 4.5.

## Explanation

Two overrides of an [extension point](../manual/graphics/effects-and-shaders/shading-language/extension-points.md) are in the same phase, and their order changes the result: one writes a stream that the other reads or writes, or both have a side effect. Nothing says which one comes first.

An effect built by the asset compiler has to state it. In a mix built at run time, the order of the mixins decides, and the log gets one information line.

## Example

The following example generates SDSL0137:

```cs
module MyPipeline
{
    stream float Value;

    [Pipeline(Steps)]
    void Run() {}
};

module StepA
{
    import MyPipeline;

    [Phase(Steps)]
    override void Run()
    {
        base.Run();
        streams.Value = 1;
    }
};

module StepB
{
    import MyPipeline;

    [Phase(Steps)]
    override void Run()
    {
        base.Run();
        streams.Value = streams.Value * 2;
    }
};
```

The following example doesn't generate SDSL0137:

```cs
module StepB
{
    import MyPipeline;

    [Phase(Steps)]
    [After(StepA)]
    override void Run()
    {
        base.Run();
        streams.Value = streams.Value * 2;
    }
};
```

## Solution

Add `[After]` to the override that has to run second, or put the two overrides in different phases.
