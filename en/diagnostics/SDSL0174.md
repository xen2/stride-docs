# Diagnostics Error SDSL0174

> cbuffer {0} mixes module and instance members ({1} is a module member, {2} is not). Split it: declare the module members in a second cbuffer {0} block (blocks with the same name are merged into one cbuffer).

Reported when your project builds, since Stride 4.5.

## Explanation

A `cbuffer` block is `module` (shared by every instance of the shader in an effect) or not as a whole, so all its members must agree. Several `cbuffer` blocks with the same name, in one shader or in several shaders, become one constant buffer of the effect, so splitting a block doesn't change how the application sets the values.

## Example

The following example generates SDSL0174:

```cs
shader MyAtmosphere : ShaderBase
{
    cbuffer PerView.Atmosphere
    {
        float BottomRadius;
        module float4 SliceDistances;
    }
};
```

The following example doesn't generate SDSL0174:

```cs
shader MyAtmosphere : ShaderBase
{
    cbuffer PerView.Atmosphere
    {
        float BottomRadius;
    }

    cbuffer PerView.Atmosphere
    {
        module float4 SliceDistances;
    }
};
```

## Solution

Move the `module` members into a second `cbuffer` block with the same name.
