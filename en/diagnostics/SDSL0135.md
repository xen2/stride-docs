# Diagnostics Error SDSL0135

> [{0}] on {1}: {2}.

Reported by the shader compiler since Stride 4.5.

## Explanation

An attribute of an [extension point](../manual/graphics/effects-and-shaders/shading-language/extension-points.md) is written the wrong way:

- `[Phases]`, `[Phase]`, `[MixinOrder]`, `[Drops]` or `[Unbind]` goes on a method, not on a class or a `cbuffer`, where it would do nothing;
- `[Phases]` goes with `pipeline` or `around`, on the first definition. A `replace` method has no phases, and an override adds one with `[Phase(MyLibrary.Name, After = Other)]`;
- `[Phases]` takes phase names, each one once, and a method has one list;
- `[MixinOrder]` goes on an override of an extension point that isn't a `replace`, or on a patch, with `After =` and `Before =`. On the method being extended, it lists classes: `[MixinOrder(A, B)]`;
- `[Drops]` goes on an override, and `[Unbind]` on the method being extended;
- on a class, `[Replaces]` takes the full name of one class;
- `[Phase]` takes one phase name, and `After =` and `Before =` with one phase name each.

## Example

The following example generates SDSL0135:

```cs
module MyModule
{
    [Phases(First, First)]
    pipeline void Run() {}
};
```

The following example doesn't generate SDSL0135:

```cs
module MyModule
{
    [Phases(First, Second)]
    pipeline void Run() {}
};
```

## Solution

Fix the attribute as the message says.
