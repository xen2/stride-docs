# Diagnostics Error SDSL0166

> {0} calls abstract method {1}, but no shader of the effect overrides it. Mix in a shader that implements {1}.

Reported when an effect is built, since Stride 4.5.

## Explanation

An abstract method has no body: a shader of the effect has to override it. When the effect calls a method that calls an abstract method, and no shader of the effect overrides it, there is no code to run.

A call in a method that is replaced is fine: if a shader overrides the calling method without calling `base`, the replaced body never runs, so the abstract method doesn't need an implementation. Before Stride 4.5, the effect failed in this case too ("Trying to call an abstract method").

## Example

The following example generates SDSL0166 when the effect mixes only `MyFilter`:

```cs
shader MyFilterBase : ComputeColor
{
    abstract float4 Filter(float4 color);

    override float4 Compute()
    {
        return Filter(float4(1, 1, 1, 1));
    }
};

shader MyFilter : MyFilterBase
{
};
```

The following examples don't generate SDSL0166:

```cs
// Filter is implemented
shader MyFilter : MyFilterBase
{
    override float4 Filter(float4 color)
    {
        return color * 0.5;
    }
};

// MyFilterBase.Compute is replaced and never runs, so Filter is never called
shader MyMask : MyFilterBase
{
    override float4 Compute()
    {
        return float4(0.5, 0.5, 0.5, 1);
    }
};
```

## Solution

Mix in a shader that overrides the abstract method, or override the calling method without calling `base`.
