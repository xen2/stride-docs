# Diagnostics Warning SDSL0213

> [Pure] module {0}: {1} in {2}() works only in a pixel shader, and a pure module can run in any stage. Compute the value in the caller and pass it as a parameter, or remove [Pure] from {0}.

Reported by the shader compiler since Stride 4.5.

## Explanation

The functions of a module marked `[Pure]` can be called from any shader stage. Some HLSL operations exist only in a pixel shader: the screen derivatives `ddx`, `ddy`, `fwidth` (and their `_coarse` / `_fine` forms), `clip` and `discard`. A pure module can't use them.

The compiler finds these operations by name. It doesn't check texture sampling with an automatic level of detail (`Sample`), which also needs derivatives: in a pure module, prefer `SampleLevel` or `SampleGrad`.

## Example

The following example generates SDSL0213 on `fwidth`:

```cs
[Pure]
module MyLines
{
    float Line(float x)
    {
        return saturate(abs(frac(x) - 0.5) / fwidth(x));
    }
};
```

The following example doesn't generate SDSL0213:

```cs
[Pure]
module MyLines
{
    float Line(float x, float width)
    {
        return saturate(abs(frac(x) - 0.5) / width);
    }
};
```

The caller, a pixel shader, passes `fwidth(x)` as `width`.

## Solution

Compute the value in the caller and pass it as a parameter, or remove `[Pure]` from the module.

To make this warning fail the build (it will be an error in a later release), set the MSBuild property `StrideShaderWarningsAsErrors` to `true` in your project.
