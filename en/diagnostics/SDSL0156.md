# Diagnostics Error SDSL0156

> {0} needs {1} values, but the initializer list has {2}. As in HLSL, braces only group: the values fill {0} in order.

Reported when your project builds, since Stride 4.5.

## Explanation

An initializer list (`{ ... }`) gives the value of a variable when it is declared. As in HLSL, the braces inside the list only group values: the compiler splits each value into its numbers, and these numbers fill the numbers of the variable in order. A matrix is filled row by row, a struct member by member, and an array element by element. So these three lines give the same matrix:

```cs
float2x2 m = { {1, 2}, {3, 4} };
float2x2 m = { 1, 2, 3, 4 };
float2x2 m = { float2(1, 2), 3, 4 };
```

The list must give exactly as many numbers as the variable has: a `float3x3` needs 9, an array of two `float2` needs 4. For an array declared without a size (`float3 offsets[] = { ... }`), the count must be a multiple of the numbers in one element, and the compiler then sets the size. DXC rejects a wrong count too ("too few elements" / "too many elements").

## Example

The following example generates SDSL0156:

```cs
shader MyEdge : ComputeColor
{
    override float4 Compute()
    {
        float3x3 kernel = { {-1, -2, -1}, {0, 0, 0}, {1, 2} };
        return float4(kernel[2], 1);
    }
};
```

The following example doesn't generate SDSL0156:

```cs
shader MyEdge : ComputeColor
{
    override float4 Compute()
    {
        float3x3 kernel = { {-1, -2, -1}, {0, 0, 0}, {1, 2, 1} };
        return float4(kernel[2], 1);
    }
};
```

## Solution

Count the numbers that the type needs, and add or remove values in the list. The inner braces don't have to match the rows: check the total.
