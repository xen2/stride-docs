# Diagnostics Error SDSL0148

> {0} and {1} both patch {2}.{3}, and nothing orders them. Add [MixinOrder(After = {0})] to the patch in {1}, or this block to the effect: extend shader {2} { [MixinOrder({0}, {1})] {3}; }

Reported when an effect is mixed, since Stride 4.5.

## Explanation

A method that is not an [extension point](../manual/graphics/effects-and-shaders/shading-language/extension-points.md) has no phases to place what changes it. When two classes of an effect `patch` it, the result would depend on the order in which the effect mixes them, which nothing states.

A patch is ordered by `[MixinOrder]` on one of the patches, also through a third patch, or by a [block](../manual/graphics/effects-and-shaders/effect-language.md#blocks) of the effect. A class also comes after the classes it inherits. A class that `[MixinOrder]` names and that isn't in the effect orders nothing.

The rule is on patches: plain overrides of an instance method follow the order of the mix.

## Example

The following example generates SDSL0148 when an effect mixes both classes:

```cs
module MyLibrary
{
    float Scale() { return 1; }
};
```

```cs
module MyDouble
{
    import MyLibrary;

    patch MyLibrary.Scale() { return next() * 2; }
};
```

```cs
module MyOffset
{
    import MyLibrary;

    patch MyLibrary.Scale() { return next() + 1; }
};
```

The following example doesn't generate SDSL0148:

```cs
module MyOffset
{
    import MyLibrary;

    [MixinOrder(After = MyDouble)]
    patch MyLibrary.Scale() { return next() + 1; }
};
```

## Solution

If you own one of the patches, add `[MixinOrder(After = ...)]` to it. If you own neither, because they are in libraries, add the block of the message to the effect: it lists the patches in the order they apply.
