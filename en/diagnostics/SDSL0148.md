# Diagnostics Error SDSL0148

> {0} and {1} both patch {2}.{3}, and nothing orders them. Add 'after {0}' to the patch in {1}, or this line to the effect: order {2}.{3}.External: {0}, {1};

Reported when an effect is mixed, since Stride 4.5.

## Explanation

A method that is not an [extension point](../manual/graphics/effects-and-shaders/shading-language/extension-points.md) has no phases to place what changes it. When two classes of an effect `patch` it, the result would depend on the order in which the effect mixes them, which nothing states.

A patch is ordered by `after` on one of the patches, also through a third patch, or by an `order` line in the effect. A class also comes after the classes it inherits. A class that `after` names and that isn't in the effect orders nothing.

The rule is on patches: plain overrides of an instance method follow the order of the mix.

## Example

The following example generates SDSL0148 when an effect mixes both classes:

```cs
module MyLibrary
{
    float Scale() { return 1; }
};
```

```cs
module MyDouble
{
    import MyLibrary;

    patch MyLibrary.Scale { return next() * 2; }
};
```

```cs
module MyOffset
{
    import MyLibrary;

    patch MyLibrary.Scale { return next() + 1; }
};
```

The following example doesn't generate SDSL0148:

```cs
module MyOffset
{
    import MyLibrary;

    patch MyLibrary.Scale after MyDouble { return next() + 1; }
};
```

## Solution

If you own one of the patches, add `after` to it. If you own neither, because they are in libraries, add the line of the message to the effect: it lists the patches in the order they apply. `External` is the implicit phase of what has no phase.
