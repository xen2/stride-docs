# Diagnostics Warning SDSL0219

> comma expression ({0}): the values before the last are dropped, the result is {1}. To build a vector, write its type: float4(...).

Reported by the shader compiler since Stride 4.5.

## Explanation

In HLSL, `(a, b, c)` is the comma operator: the compiler computes `a`, then `b`, then `c`, and the result is `c` alone. It doesn't build a vector. When the result goes into a vector, the last value is copied to every component: `(1, 0, 0, 1)` gives `float4(1, 1, 1, 1)`, white, not red.

The compiler reports the warning when a value before the last has no side effect (no assignment, `++`, `--` or method call): that value is computed for nothing, so a vector was most likely intended. FXC reports the same case as warning X3081.

## Example

The following example generates SDSL0219:

```cs
shader MyRed : ComputeColor
{
    override float4 Compute()
    {
        return (1, 0, 0, 1);
    }
};
```

The following example doesn't generate SDSL0219:

```cs
shader MyRed : ComputeColor
{
    override float4 Compute()
    {
        return float4(1, 0, 0, 1);
    }
};
```

A comma expression where every dropped value has a side effect doesn't generate SDSL0219 either:

```cs
int i = 0;
int j = (i++, i * 2); // i is 1, j is 2
```

## Solution

To build a vector, write its type before the parentheses: `float4(1, 0, 0, 1)`. If you only want the last value, remove the other values.

To make this warning fail the build, set the MSBuild property `StrideShaderWarningsAsErrors` to `true` in your project.
