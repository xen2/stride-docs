# Diagnostics Error SDSL0247

> {0} is a module, but it is in the composition {1}. A module goes to the root of the effect, so a call through a composition can reach the wrong one. Compose a shader, and call the module from it.

Reported by the shader compiler since Stride 4.5, when it builds an effect, in the asset build and at run time.

## Explanation

A [composition](../manual/graphics/effects-and-shaders/shading-language/composition.md) holds shaders: each slot has its own instance. A [module](../manual/graphics/effects-and-shaders/shading-language/shaders-and-modules.md) exists once per effect, at the root. So a call through the slot finds a method by its name at the root: with two modules in two slots, both calls go to the first one.

A module that a composed shader imports is fine. The error is about a module named as the value of the slot.

## Example

The following example generates SDSL0247 when an effect sets `Light` to `MyModel`:

```cs
module MyModel
{
    float3 DirectLight() { ... }
};

shader MyRoot
{
    compose MyLight Light;
};
```

```cs
effect MyEffect
{
    mixin MyRoot;
    mixin compose Light = MyModel;
};
```

The following example doesn't generate SDSL0247:

```cs
shader MyModelNode : MyLight
{
    override float3 DirectLight() { return MyModel.DirectLight(); }
};
```

```cs
effect MyEffect
{
    mixin MyRoot;
    mixin compose Light = MyModelNode;
};
```

## Solution

Write a small shader of the slot's type that calls the module, and compose that shader.
