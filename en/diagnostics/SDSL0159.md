# Diagnostics Error SDSL0159

> {0}: {1} sees no stream named {2}{3}. A stream is a member declared with stream, in the class or in a class it inherits or imports: streams.{2} reaches only those.

Reported by the shader compiler since Stride 4.5.

## Explanation

The name after `streams.` (or after a variable of type `Streams`, `Input` or `Output`) is not the name of a stream that the class sees: one it declares with `stream`, or one of a class it inherits or imports. When the class has something else of that name, the message says what it is: a local variable or a parameter, a member that is not a stream, a method, or a constant.

Only streams count after `streams.`: a local variable, a parameter, a member or a method with the name of a stream doesn't hide it.

## Example

The following example generates SDSL0159 in `MyLighting`, because `weight` is a member that is not a stream:

```cs
shader MyLighting
{
    float weight;

    float Get()
    {
        return streams.weight;
    }
};
```

The following example doesn't generate SDSL0159. `streams.weight` is the stream of `MySurface`, and `weight` alone is the local variable:

```cs
shader MySurface
{
    stream float weight;
};

shader MyLighting : MySurface
{
    float Get()
    {
        float weight = 0.5;
        return streams.weight * weight;
    }
};
```

## Solution

Declare the stream with `stream` in the class, or inherit or import the class that declares it. If you meant the member, the local variable or the parameter, remove `streams.`.
