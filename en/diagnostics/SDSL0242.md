# Diagnostics Warning SDSL0242

> & within |: {0} computes {1} first. Add parentheses around it to make it clear.

Reported by the shader compiler since Stride 4.5.

## Explanation

In HLSL, as in C, `&` is computed before `|`: `a | b & c` is `a | (b & c)`. The code is often right, but a reader can easily take it for `(a | b) & c`. DXC reports the same case (`-Wbitwise-op-parentheses`).

## Example

The following example generates SDSL0242:

```cs
shader MyFlags : ComputeColor
{
    uint Flags;

    override float4 Compute()
    {
        uint visible = Flags & 1 | Flags & 4;
        return visible != 0 ? 1 : 0;
    }
};
```

The following example doesn't generate SDSL0242:

```cs
shader MyFlags : ComputeColor
{
    uint Flags;

    override float4 Compute()
    {
        uint visible = (Flags & 1) | (Flags & 4);
        return visible != 0 ? 1 : 0;
    }
};
```

## Solution

Add parentheses around the `&` operation.
