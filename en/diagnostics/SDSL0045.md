# Diagnostics Error SDSL0045

> `stage` is now `module`: write `module`. The Stride project upgrade does it for the shaders of your project. A shader in a package needs a new version of that package.

Reported when your project builds, since Stride 4.5.

## Explanation

Before Stride 4.5, a member or a method that exists once per effect was marked `stage`. Stride 4.5 writes it `module` (see [Shaders and modules](../manual/graphics/effects-and-shaders/shading-language/shaders-and-modules.md)), and `stage` is an error.

The project upgrade to Stride 4.5 rewrites the `.sdsl` files of your project. So you usually see this error for shader text that the upgrade doesn't reach:

- a shader of a package built for Stride 4.4: the path in the message is in your NuGet folder;
- shader text that your game gives at run time (`AddShaderSource`, a file that your code reads, generated text).

## Example

The following example generates SDSL0045:

```cs
shader MyWaterNode : ComputeColor
{
    stage float WaveSpeed;

    override float4 Compute()
    {
        return float4(WaveSpeed, 0, 0, 1);
    }
};
```

The following example doesn't generate SDSL0045:

```cs
shader MyWaterNode : ComputeColor
{
    module float WaveSpeed;

    override float4 Compute()
    {
        return float4(WaveSpeed, 0, 0, 1);
    }
};
```

## Solution

Write `module` instead of `stage`. In a shader of your project, the project upgrade does it for you.

For a shader of a package, ask its author for a version made for Stride 4.5, or copy the shader into your project. As the author of a package, upgrade the project of the package (open it in Game Studio, or run `stride upgrade`), then publish a new version.
