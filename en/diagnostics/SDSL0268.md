# Diagnostics Error SDSL0268

> On Direct3D 11, a texture array index must be a constant once the methods are inlined: FXC can't index textures with a value. Use a literal, a static const value or a generic parameter, with one shader permutation per value.

Reported when an effect is compiled for Direct3D 11, since Stride 4.5.

## Explanation

The Direct3D 11 shader compiler (FXC, shader model 5.0) has no instruction to read a texture from an index that it doesn't know. So on Direct3D 11, each index of a texture array must be a constant. Stride inlines the methods first: an index given to a method as a parameter becomes a constant when the caller gives a constant.

Direct3D 12 and Vulkan index a texture array with a value, such as a `cbuffer` member.

## Example

The following example generates SDSL0268 on Direct3D 11:

```cs
shader MyMaterial : ShaderBase
{
    rgroup PerMaterial
    {
        Texture2D Textures[4];
    }
    cbuffer PerMaterial
    {
        module uint TextureIndex;
    };

    float4 Read(float2 uv) { return Textures[TextureIndex].Sample(LinearSampler, uv); }
};
```

The following example doesn't generate SDSL0268:

```cs
shader MyMaterial<int TextureIndex> : ShaderBase
{
    rgroup PerMaterial
    {
        Texture2D Textures[4];
    }

    float4 Read(int index, float2 uv) { return Textures[index].Sample(LinearSampler, uv); }
    float4 Read(float2 uv) { return Read(TextureIndex, uv); }
};
```

## Solution

Use a literal, a `static const` value or a generic parameter, and one shader permutation for each value. On Direct3D 12 and Vulkan, keep the value: `#if STRIDE_GRAPHICS_API_DIRECT3D11` chooses between the two forms in one shader.
