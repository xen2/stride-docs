# Diagnostics Error SDSL0154

> the block extend shader {0} ({1}) names {2}, but {0} is in the effect and {3}. A block is about a method of its class, or one the class contributes to, written Owner.Method.

Reported by the shader compiler since Stride 4.5, when the effect is mixed.

## Explanation

A [block](../manual/graphics/effects-and-shaders/effect-language.md#blocks) names a method of its class, `Method`, or a method its class contributes to, `Owner.Method`. The class of the block is in this effect, and:

- it has no extension point of that name, so the block could never do anything. `[MixinOrder]` can also be about a method that classes `patch`;
- or it doesn't contribute to `Owner.Method`;
- or the method has several overloads, and the block doesn't say which one: write the parameter types, `Method(float3, int)`;
- or `[Unbind]` names a method that isn't an extension point.

Usually one of the names is misspelled, or `Owner` isn't the class of the first definition.

A block about a class that exists and isn't in the effect is not an error: an effect can be mixed in many ways. A class that exists nowhere is [SDSL0158](SDSL0158.md).

## Example

The following example generates SDSL0154:

```cs
module MyPipeline
{
    [Phases(First, Second)]
    pipeline void Run() {}
};

effect MyEffect
{
    mixin MyPipeline;
    extend shader MyPipeline { [Unbind(Phases = { First })] Runn; }
}
```

The following example doesn't generate SDSL0154:

```cs
effect MyEffect
{
    mixin MyPipeline;
    extend shader MyPipeline { [Unbind(Phases = { First })] Run; }
}
```

## Solution

Name a method of the class, or `Owner.Method` for a method it contributes to, with the class of the first definition. If the method has no kind, add one to its first definition.
