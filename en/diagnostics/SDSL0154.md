# Diagnostics Error SDSL0154

> a linkage rule of the effect names {0}.{1}, but {0} is in the effect and has no extension point {1}. Check the names: a rule is about a method whose first definition in {0} declares a kind, or the patches of a method in phase External.

Reported by the shader compiler since Stride 4.5.

## Explanation

A [linkage rule](../manual/graphics/effects-and-shaders/effect-language.md) names the first definition of a method, `Owner.Method`. The class `Owner` is in this effect, and it declares no [extension point](../manual/graphics/effects-and-shaders/shading-language/extension-points.md) of that name, so the rule could never do anything. Usually one of the names is misspelled, or `Owner` isn't the class of the first definition.

A rule about a class that isn't in the effect is not an error: an effect can be mixed in many ways.

## Example

The following example generates SDSL0154:

```cs
module MyPipeline
{
    [Pipeline(First, Second)]
    void Run() {}
};

effect MyEffect
{
    mixin MyPipeline;
    unbind MyPipeline.Runn.First;
}
```

The following example doesn't generate SDSL0154:

```cs
effect MyEffect
{
    mixin MyPipeline;
    unbind MyPipeline.Run.First;
}
```

## Solution

Name the class of the first definition and its method. If the method has no kind, add one to its first definition.
