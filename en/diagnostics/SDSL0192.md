# Diagnostics Error SDSL0192

> {0}.{1}: {1} is {2}, so '{0}.' doesn't apply to it. Write {1}.

Reported when your project builds, since Stride 4.5.

## Explanation

`this.X` reads the member `X` of the shader instance, as `X` does, also where a local variable has the same name. Two uses have no meaning, so the compiler rejects them:

- `this.X` where `X` is a `stage` member: a stage member is shared by every instance of the shader in the effect, so it is not a member of this instance.
- `base.X` where `X` is a variable: `base` calls the method that an override replaces. Variables are not overridden, so `base.X` would be `X`.

`this.Method()` and `base.Method()` are not concerned.

## Example

The following example generates SDSL0192:

```cs
shader MyTint : ComputeColor
{
    stage float4 Tint;

    override float4 Compute()
    {
        return this.Tint;
    }
};
```

The following example doesn't generate SDSL0192:

```cs
shader MyTint : ComputeColor
{
    stage float4 Tint;

    override float4 Compute()
    {
        return Tint;
    }
};
```

## Solution

Write the member name without `this.` or `base.`.
