# Diagnostics Error SDSL0149

> macro {0} is set inside the composition {1}. A macro belongs to the whole effect: set it at the top level of the effect. In a composition, use a generic for a value, or a separate class for a different shape.

Reported when an effect is generated, since Stride 4.5.

## Explanation

A macro applies to every class of an effect. A class in a composition can share its module part with the rest of the effect, so a macro on one node of the tree can't give that node its own code.

`mixin macro` therefore works at the top level of an effect, and in an effect you mix with `mixin`. Inside a `mixin compose`, or in an effect you mix with `mixin compose`, it is this error.

## Example

The following example generates SDSL0149:

```cs
effect MyLayer
{
    mixin macro USE_DETAIL = 1;
    mixin MyLayerShader;
};

effect MyEffect
{
    mixin MyBase;
    mixin compose Layer = MyLayer;
};
```

## Solution

Choose one of these, depending on what the macro does.

For a value that changes per composition, use a generic:

```cs
shader MyLayerShader<int Detail> : MyLayerBase
{
    override float4 Compute() { return Detail * base.Compute(); }
};
```

```cs
effect MyLayer
{
    mixin MyLayerShader<1>;
};
```

For a different shape, such as other methods or other members, write a separate class and mix the one you need:

```cs
effect MyLayer
{
    if (MyParameters.Detailed)
        mixin MyDetailedLayerShader;
    else
        mixin MyLayerShader;
};
```

For a value of the whole effect, set the macro at the top level:

```cs
effect MyEffect
{
    mixin macro USE_DETAIL = 1;
    mixin MyBase;
    mixin compose Layer = MyLayer;
};
```

From C#, macros go on an @'Stride.Shaders.EffectSource', next to the root of the tree:

```cs
var effect = new EffectSource(root)
{
    Macros = { new ShaderMacro("USE_DETAIL", 1) },
};
```
