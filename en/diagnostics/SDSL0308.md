# Diagnostics Error SDSL0308

> {1} doesn't declare {0} with the macros of this compile: it is inside an #if that is off, or the file changed since the last build.

Reported when a shader loads, since Stride 4.5.

## Explanation

The build finds the shaders of a file with a quick read of its text. That read doesn't run the preprocessor, so it sees both sides of an `#if`. A shader is compiled only when something asks for it, with the macros of that compile. If the macros turn off the only declaration of the shader, there is nothing to compile.

You also get this error if you remove a shader from a file while a game runs, and something still asks for it.

## Example

The following file generates SDSL0308 when an effect asks for `ComputeColorFade` and `USE_FADE` isn't defined:

```cs
namespace MyGame;

shader ComputeColorTint : ComputeColor
{
    override float4 Compute() { return float4(1, 0, 0, 1); }
};

#ifdef USE_FADE
shader ComputeColorFade : ComputeColor
{
    override float4 Compute() { return float4(0, 0, 0, 1); }
};
#endif
```

## Solution

Define the macro in the effect that asks for the shader, or move the shader out of the `#if`. If the file changed, build the project again.
