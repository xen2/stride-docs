# Diagnostics Error SDSL0291

> {0} of the cbuffer {1} is the [CSharp] struct {2}, whose field {3} is at offset {4} in a cbuffer and {5} in C#. Add a padding field before {3} in {2}{6}, or write [CSharp(SkipLayoutCheck = true)] on {2} if another C# struct fills this cbuffer.

Reported when an effect is compiled (in the asset build, or when the game compiles it), since Stride 4.5.

## Explanation

A `[CSharp]` struct has one C# layout, the tight layout of a structured buffer. A cbuffer packs a struct in 16-byte rows, so a field that would cross a row starts the next one: with `float3 a; float3 b;`, `b` is at 16 in a cbuffer and at 12 in C#. Then the C# struct doesn't fill the cbuffer right.

## Example

The following example generates SDSL0291:

```cs
[CSharp] struct Light { float3 direction; float3 color; };
cbuffer PerLight { Light MainLight; };
```

The following example doesn't generate SDSL0291:

```cs
[CSharp] struct Light { float3 direction; float pad0; float3 color; };
cbuffer PerLight { Light MainLight; };
```

## Solution

Add the padding field the message gives, so that both layouts are the same. If the cbuffer is filled with another C# struct, write `[CSharp(SkipLayoutCheck = true)]` on the struct.
