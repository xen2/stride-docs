# Diagnostics Warning SDSL0210

> [Pure] module {0} uses {1}, which is not a pure module. Mark {1} [Pure] if it can be, or remove [Pure] from {0}.

Reported by the shader compiler since Stride 4.5.

## Explanation

A module marked `[Pure]` has no state (see [SDSL0209](SDSL0209.md)). It may import other modules, or call their functions by name (`Math.Hash(...)`), only if they are pure too: a module without `[Pure]` can have state, and then the pure module would depend on it.

## Example

The following example generates SDSL0210 on `Global`:

```cs
[Pure]
module MyPulse
{
    float Pulse(float speed)
    {
        return 0.5 + 0.5 * sin(Global.Time * speed);
    }
};
```

The following example doesn't generate SDSL0210:

```cs
[Pure]
module MyPulse
{
    float Pulse(float time, float speed)
    {
        return 0.5 + 0.5 * sin(time * speed);
    }
};
```

## Solution

Pass the value as a parameter (here the caller passes `Global.Time`), mark the used module `[Pure]` if it has no state, or remove `[Pure]`.

To make this warning fail the build (it will be an error in a later release), set the MSBuild property `StrideShaderWarningsAsErrors` to `true` in your project.
