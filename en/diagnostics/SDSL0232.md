# Diagnostics Warning SDSL0232

> {0} has lower precedence than {1}: {2} computes {3} first. Add parentheses to make it clear.

Reported by the shader compiler since Stride 4.5.

## Explanation

In HLSL, as in C, the comparison operators (`==`, `!=`, `<`, `<=`, `>`, `>=`) are computed before the bitwise operators `&`, `|` and `^`. So `flags & 1 == 0` is `flags & (1 == 0)`, which is always 0, not `(flags & 1) == 0`.

The compiler reports the warning when a comparison without parentheses is a side of `&`, `|` or `^`. Sometimes the code is right (`a > b & c` meant `(a > b) & c`), but the reader can't tell. DXC reports the same case (`-Wparentheses`).

`&`, `|` and `^` also work on `bool` values: as in HLSL, the result is an `int` (`true & true` is `1`).

## Example

The following example generates SDSL0232:

```cs
shader MyMirror : ComputeColor, Texturing
{
    float Border;
    bool SwitchSides;

    override float4 Compute()
    {
        float2 uv = streams.TexCoord;
        if (uv.y > Border & !SwitchSides)
            uv.y = 1 - uv.y;
        return float4(uv, 0, 1);
    }
};
```

The following example doesn't generate SDSL0232:

```cs
shader MyMirror : ComputeColor, Texturing
{
    float Border;
    bool SwitchSides;

    override float4 Compute()
    {
        float2 uv = streams.TexCoord;
        if ((uv.y > Border) & !SwitchSides)
            uv.y = 1 - uv.y;
        return float4(uv, 0, 1);
    }
};
```

## Solution

Add parentheses around the part that must be computed first. For a condition on two `bool` values, `&&` and `||` are usually what was meant: they also skip the second side when the first one decides.
