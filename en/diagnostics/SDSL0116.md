# Diagnostics Error SDSL0116

> {0}.{1}({2}) at line {3} is marked 'override', but no inherited method {1} has this signature (inherited: {4}). Use the signature of the inherited method.

Reported by the shader compiler since Stride 4.5. Before, the same mistake failed with the message "Sequence contains no elements".

## Explanation

`override` replaces an inherited method, so the overriding method has the signature of the inherited one: the same parameter types and the same return type. When a parent declares a method of that name, but with other parameters or another return type, the compiler doesn't know which method is replaced.

The message lists the signatures of the inherited methods of that name.

## Example

The following example generates SDSL0116:

```cs
shader ColorProvider
{
    float4 Compute() { return 0; }
};

shader ScaledColor : ColorProvider
{
    // ColorProvider.Compute() takes no parameter
    override float4 Compute(float scale)
    {
        return scale;
    }
};
```

The following example doesn't generate SDSL0116:

```cs
shader ScaledColor : ColorProvider
{
    float Scale;

    override float4 Compute()
    {
        return Scale;
    }
};
```

## Solution

Use the signature of the inherited method. If the method is a new one (an overload), remove `override`.
