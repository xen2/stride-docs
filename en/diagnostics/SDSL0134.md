# Diagnostics Error SDSL0134

> {0}: member {2} ({3}) of the [PushConstant] cbuffer {1} is at byte {4} of the push-constant block, but a {3} must start at a multiple of {5} bytes, so that the C# struct given to SetPushConstants has the same layout on every graphics API. Move it to such an offset (add a member before it), or reorder the members (for example the vectors first).

Reported by the shader compiler since Stride 4.5, when it builds an effect.

## Explanation

The members of the [push constants](../manual/graphics/effects-and-shaders/shading-language/shaders-and-modules.md#push-constants) are packed one after the other, with no padding, in the order of the effect. So a C# struct with the same members, in the same order, has the same layout. But a 2-component vector must start at a multiple of 8 bytes, and a 4-component vector at a multiple of 16 bytes, on every graphics API. The compiler doesn't add padding before them (the C# struct would not have it): it reports the member instead.

The offset is in the effect's block, which can join cbuffers of several classes, so a cbuffer that is fine alone can be misaligned in an effect.

## Example

The following example generates SDSL0134:

```cs
shader MyShading
{
    [PushConstant] cbuffer PerDraw
    {
        module uint DrawIndex;
        module float2 Scale;
    };
};
```

The message is `MyShading: member Scale (float2) of the [PushConstant] cbuffer PerDraw is at byte 4 of the push-constant block, but a float2 must start at a multiple of 8 bytes, ...`

The following example doesn't generate SDSL0134:

```cs
shader MyShading
{
    [PushConstant] cbuffer PerDraw
    {
        module float2 Scale;
        module uint DrawIndex;
    };
};
```

## Solution

Put the vectors first, largest first, or add a member before the vector (and the same member in the C# struct).
