# Diagnostics Error SDSL0158

> a linkage rule of the effect names the class {0}, which doesn't exist. Check the name. If the class comes from a package, reference that package from the project, or remove the rule.

Reported by the shader compiler since Stride 4.5, when the effect is mixed: in the asset build and at run time.

## Explanation

A [linkage rule](../manual/graphics/effects-and-shaders/effect-language.md) names classes: `Owner` in `Owner.Method`, and the classes of `order`, `bind` and `unbind`. The shader compiler can't find one of them anywhere, so the rule could never do anything. Usually the name is misspelled.

A class that exists and isn't in this effect is not an error: an effect can be mixed in many ways. A class of a package that the project doesn't reference doesn't exist for the compiler, so a rule about it is this error.

When a class of that name exists in another namespace, the message says which `using` is missing.

## Example

The following example generates SDSL0158:

```cs
module MyPipeline
{
    [Pipeline(First, Second)]
    void Run() {}
};

effect MyEffect
{
    mixin MyPipeline;
    unbind MyPipline.Run.First;
}
```

The following example doesn't generate SDSL0158:

```cs
effect MyEffect
{
    mixin MyPipeline;
    unbind MyPipeline.Run.First;
}
```

## Solution

Check the name. If the class comes from a package, reference that package from the project. If the project can't have that package, remove the rule, or move it to a project that has it.
