# Diagnostics Warning SDSL0207

> {0}.{1}() is 'module' but overrides the instance method {2}.{1}. If {0} is used in a composition, an instance method has one override chain per instance. Remove 'module', mark {2}.{1} 'module', or mark {0} [Root] if it is only mixed at the root of an effect.

Reported by the shader compiler since Stride 4.5.

## Explanation

An instance method (a method without `module`) has one chain of overrides per instance: when a material uses the shader in two slots, each slot calls its own chain. An `override module` exists once per effect, in the root of the effect, so the instance's chain never reaches it. When the shader is used in a composition, the effect fails to build.

At the root of an effect there is only one node, so both kinds work there.

The compiler checks this when the class compiles, unless the class is root-only (see [SDSL0119](SDSL0119.md)).

## Example

The following example generates SDSL0207 on `Compute`:

```cs
shader MyRedColor : ComputeColor
{
    override module float4 Compute()
    {
        return float4(1, 0, 0, 1);
    }
};
```

The following example doesn't generate SDSL0207:

```cs
shader MyRedColor : ComputeColor
{
    override float4 Compute()
    {
        return float4(1, 0, 0, 1);
    }
};
```

## Solution

Remove `module` from the override. If the method really should exist once per effect, mark the overridden method `module` in the parent class (if it is yours). If the shader is only mixed at the root of an effect, you can mark it `[Root]` instead.

To make this warning fail the build (it will be an error in a later release), set the MSBuild property `StrideShaderWarningsAsErrors` to `true` in your project.
