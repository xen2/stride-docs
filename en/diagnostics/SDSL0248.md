# Diagnostics Error SDSL0248

> The call {0} in {1} is ambiguous: {2} and {3} both declare it, and neither comes from the other, so only the order of the parents and imports would say which one runs. Write {2}.{4}(...) or {3}.{4}(...).

Reported by the shader compiler since Stride 4.5, when it compiles a class, in the asset build and at run time.

## Explanation

A call with no class in front of it, `Helper(1.0)` or `this.Helper(1.0)`, needs one method to answer. When a class inherits or imports two unrelated classes that declare one method name with the same parameters, only their order says which one runs, so swapping two `import` lines changes what the shader computes.

This is an error whatever the two bodies are. Two copies that are identical today can differ tomorrow, and the compiler can't know which one you meant.

These are not ambiguous:

- A method of the class itself.
- An override, against the method it overrides.
- Two overrides of one method, in two parents: they are one chain.
- One class reached twice, through two parents or two imports.
- Two classes that each call their own import or parent, mixed together: each call stays with its own class.

## Example

The following example generates SDSL0248:

```cs
module MyColors
{
    float3 Tint(float3 color) { return color * 0.5; }
};

module MyOtherColors
{
    float3 Tint(float3 color) { return color.bgr; }
};

shader MyShader
{
    import MyColors;
    import MyOtherColors;

    float3 Compute(float3 color) { return Tint(color); }
};
```

The following example doesn't generate SDSL0248:

```cs
shader MyShader
{
    import MyColors;
    import MyOtherColors;

    float3 Compute(float3 color) { return MyOtherColors.Tint(color); }
};
```

## Solution

Write the name of the class in front of the call. To use only one of the two classes, remove the other from the parents and imports.

The upgrade doesn't fix this, because only you know which function you meant.
