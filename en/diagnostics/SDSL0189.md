# Diagnostics Error SDSL0189

> This texture offset is not a constant, even with the methods inlined and the [unroll] loops unrolled. Use a literal, a static const value, or the counter of an [unroll] loop with constant bounds; a value from a cbuffer, a stream or a loop without [unroll] can't be an offset.

Reported when an effect is compiled, since Stride 4.5.

## Explanation

The offset argument of `Sample`, `SampleLevel`, `SampleCmp`, `Load` and the other texture methods must be a constant, as in HLSL. It can come through a method parameter or the counter of an `[unroll]` loop: like DXC, Stride inlines the methods and unrolls those loops, and the offset becomes a constant. A value read from a cbuffer, a stream, a texture or a buffer, or the counter of a loop that is not unrolled, never becomes one.

Only the `Gather` methods take an offset that is not a constant.

## Example

The following example generates SDSL0189:

```cs
shader Blur : ImageEffectShader
{
    int Radius;

    stage override float4 Shading()
    {
        float4 sum = 0;
        for (int i = -Radius; i <= Radius; i++)
            sum += Texture0.Sample(PointSampler, streams.TexCoord, int2(i, 0));
        return sum / (2 * Radius + 1);
    }
};
```

The following example doesn't generate SDSL0189:

```cs
shader Blur : ImageEffectShader
{
    static const int Radius = 2;

    float4 Tap(int2 offset)
    {
        return Texture0.Sample(PointSampler, streams.TexCoord, offset);
    }

    stage override float4 Shading()
    {
        float4 sum = 0;
        [unroll]
        for (int i = -Radius; i <= Radius; i++)
            sum += Tap(int2(i, 0));
        return sum / (2 * Radius + 1);
    }
};
```

## Solution

Make the offset a constant: a literal, a `static const` value, or the counter of an `[unroll]` loop with constant bounds. For an offset that must change at run time, add it to the texture coordinates instead (`uv + offset * TexelSize`).
