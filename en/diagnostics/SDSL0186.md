# Diagnostics Error SDSL0186

> The destination of {0}, {1}, is {2}: other threads don't see it. Use an element of a RWStructuredBuffer, RWBuffer or RWTexture, or a groupshared variable.

Reported when your project builds, since Stride 4.5.

## Explanation

An `Interlocked*` intrinsic changes memory that several threads share. Its destination must be:

- an element of a `RWStructuredBuffer` (or a member of one), a `RWBuffer` or a `RWTexture`,
- or a `groupshared` variable (shared by the threads of a group).

A local variable, a parameter, a `static` variable or a stream belongs to one thread. A constant buffer member and a read-only buffer (`StructuredBuffer`, `Buffer`) can't be written. A value, such as `Values[0] + 1`, is not a variable.

## Example

The following example generates SDSL0186:

```cs
shader Counter : ComputeShaderBase
{
    RWStructuredBuffer<uint> Result;

    override void Compute()
    {
        uint count = 0;
        InterlockedAdd(count, 1);
        Result[0] = count;
    }
};
```

The following example doesn't generate SDSL0186:

```cs
shader Counter : ComputeShaderBase
{
    RWStructuredBuffer<uint> Result;

    override void Compute()
    {
        InterlockedAdd(Result[0], 1);
    }
};
```

## Solution

Use a read-write buffer or texture element, or a `groupshared` variable. If only one thread uses the value, you don't need an atomic operation: write `count += 1;`.
