# Diagnostics Warning SDSL0206

> {0}.{1}() overrides the module method {2}.{1} but is not 'module'. If {0} is used in a composition, a module method has one override chain per effect. Write 'override module', or mark {0} [Root] if it is only mixed at the root of an effect.

Reported by the shader compiler since Stride 4.5.

## Explanation

A module method (a `module` method of a shader, or a method of a module such as `TransformationBase` or `ShaderBase`) exists once per effect, and so does the chain of its overrides. A plain `override` is an instance method: in a composition, it is in the composition's own node, and the module method's chain never reaches it. When the shader is used in a composition, the effect fails to build.

At the root of an effect there is only one node, so both kinds work there.

The compiler checks this when the class compiles, unless the class is root-only (see [SDSL0119](SDSL0119.md)).

## Example

The following example generates SDSL0206 on `PreTransformPosition`:

```cs
shader MyWind
{
    import TransformationBase;
    import PositionStream4;

    override void PreTransformPosition()
    {
        streams.Position.x += sin(Global.Time) * 0.1;
    }
};
```

The following example doesn't generate SDSL0206:

```cs
shader MyWind
{
    import TransformationBase;
    import PositionStream4;

    module override void PreTransformPosition()
    {
        streams.Position.x += sin(Global.Time) * 0.1;
    }
};
```

## Solution

Write `module override`. If the shader is only mixed at the root of an effect, you can mark it `[Root]` instead.

To make this warning fail the build (it will be an error in a later release), set the MSBuild property `StrideShaderWarningsAsErrors` to `true` in your project.
