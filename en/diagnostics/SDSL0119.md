# Diagnostics Error SDSL0119

> {0} can only be mixed at the root of an effect ([Root] on it, or on a class it inherits or imports), but it is in the composition {1}. Mix it at the root, or remove [Root].

Reported by the shader compiler since Stride 4.5, when it builds an effect.

## Explanation

Some shaders are the effect itself: post effects, sprite and particle shaders, compute shaders, and the shaders that define the entry points (`VSMain`, `PSMain`, `Shading`). They are **root-only**: they can be mixed at the root of an effect, but not used in a [composition](../manual/graphics/effects-and-shaders/shading-language/composition.md) slot.

A class is root-only when:

- it has the `[Root]` attribute, or
- it is a shader that inherits a root-only shader, or imports a module that has `[Root]`.

A shader that inherits or imports a `[Root]` class directly is root-only; importing a module that imports it doesn't count.

The engine marks `ShaderBase`, `ShadingBase`, `ImageEffectShader`, `ComputeShaderBase`, `SpriteBase` and `ParticleBase` (and a few effect features) with `[Root]`. So a post effect, which imports `ImageEffectShader`, is root-only.

A root-only shader may read its own members from module code, because at the root it is the only instance. In a composition it would be one instance among several, and that code would read the wrong values.

The composition in the message is written from the root of the effect down, as in an effect file: `Root.Computes[1].Index` is the slot `Index` of the second shader of the array `Computes`, in the slot `Root` of the root shader.

### Shaders that only need the streams

Before Stride 4.5, a shader used in a composition often inherited `ShaderBase` or `ComputeShaderBase` only to read their streams (`streams.ShadingPosition`, `streams.DispatchThreadId`, ...). Both are `[Root]` now. Their streams are also in modules that are not root-only:

| Root-only module | Streams module | Streams |
|---|---|---|
| `ShaderBase` | `ShaderBaseStream` | `ShadingPosition`, `ColorTarget`, `Depth`, `IsFrontFace`, `InstanceID`, ... |
| `ComputeShaderBase` | `ComputeShaderStreams` | `DispatchThreadId`, `GroupId`, `GroupThreadId`, `GroupIndex`, `ThreadGroupCount`, `ThreadCountX` / `Y` / `Z`, ... and `IsFirstThreadOfGroup()` |

A shader used in a composition imports the streams module. The root shader of the effect (for example the compute shader that composes it) still imports `ComputeShaderBase`, which writes these streams. The project upgrade makes this change for shaders written before 4.5.

## Example

The following example generates SDSL0119 when an effect uses `MyTintColor` as a material color (in a composition):

```cs
// A post effect
shader MyTint
{
    import ImageEffectShader;

    float4 Tint;

    module override float4 Shading()
    {
        return base.Shading() * Tint;
    }
};

// Reuses the post effect's Tint as a material color
shader MyTintColor : ComputeColor, MyTint
{
    override float4 Compute()
    {
        return Tint;
    }
};
```

The following example doesn't generate SDSL0119:

```cs
shader MyTintColor : ComputeColor
{
    float4 Tint;

    override float4 Compute()
    {
        return Tint;
    }
};
```

The following example generates SDSL0119 when a compute shader composes `MyThreadColor` (a color computed per thread):

```cs
shader MyThreadColor : ComputeColor
{
    import ComputeShaderBase;

    override float4 Compute()
    {
        return float4(streams.DispatchThreadId, 1);
    }
};
```

The following example doesn't generate SDSL0119:

```cs
shader MyThreadColor : ComputeColor
{
    import ComputeShaderStreams;

    override float4 Compute()
    {
        return float4(streams.DispatchThreadId, 1);
    }
};
```

## Solution

Mix the shader at the root of the effect, or write a separate shader for the composition that doesn't inherit the root-only shader. If the shader only reads the streams of `ShaderBase` or `ComputeShaderBase`, import `ShaderBaseStream` or `ComputeShaderStreams` instead. If you put `[Root]` on your own shader and it must also work in compositions, remove `[Root]`.

Shader code generated at run time (by a tool or a library) doesn't go through the project upgrade: change the generator so that it writes the import of the streams module.
