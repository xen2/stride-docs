# Diagnostics Warning SDSL0243

> && within ||: {0} computes {1} first. Add parentheses around it to make it clear.

Reported by the shader compiler since Stride 4.5.

## Explanation

In HLSL, as in C, `&&` is computed before `||`: `a && b || c` is `(a && b) || c`. The code is often right, but a reader can easily take it for `a && (b || c)`. DXC reports the same case (`-Wlogical-op-parentheses`).

## Example

The following example generates SDSL0243:

```cs
shader MyRange : ComputeColor, Texturing
{
    override float4 Compute()
    {
        float2 uv = streams.TexCoord;
        bool inside = uv.x > 0.25 && uv.x < 0.75 || uv.y > 0.5;
        return inside ? 1 : 0;
    }
};
```

The following example doesn't generate SDSL0243:

```cs
shader MyRange : ComputeColor, Texturing
{
    override float4 Compute()
    {
        float2 uv = streams.TexCoord;
        bool inside = (uv.x > 0.25 && uv.x < 0.75) || uv.y > 0.5;
        return inside ? 1 : 0;
    }
};
```

## Solution

Add parentheses around the `&&` operation.
