# Diagnostics Error SDSL0252

> phase {0}, added by {1}, has a plain name. Only the owner of {2} declares plain names, in [Phases]: give the phase a prefix of your own, such as {3}.

Reported by the shader compiler since Stride 4.5, and when an effect project builds for a phase that a block adds.

## Explanation

A class that doesn't own a method can [add a phase](../manual/graphics/effects-and-shaders/shading-language/extension-points.md#add-a-phase) to it. The owner names its phases in `[Phases]`, and it can add more in a later version. A prefix keeps the phases of others apart from them, and from each other: `MyLibrary.Wind` never meets a `Wind` that the owner adds one day. The prefix works like the name of a package: two libraries that write the same full name share that phase on purpose.

## Example

The following example generates SDSL0252:

```cs
module MyPipeline
{
    [Phases(First, Second)]
    pipeline void Run() {}
};

module MyStep
{
    import MyPipeline;

    [Phase(Wind, After = First)]
    extend MyPipeline.Run() { ... }
};
```

The following example doesn't generate SDSL0252:

```cs
module MyStep
{
    import MyPipeline;

    [Phase(MyLibrary.Wind, After = First)]
    extend MyPipeline.Run() { ... }
};
```

## Solution

Give the phase a prefix, such as the name of your library, and use the full name wherever you name it.
