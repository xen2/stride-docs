# Diagnostics Error SDSL0114

> {0}.{1}({2}) at line {3} implements abstract method {4}.{1} but is not marked 'override'. Add the 'override' keyword.

Reported by the shader compiler since Stride 4.4. The first 4.4 versions report it as an error; later 4.4 versions report a warning and compile the method as an override. Since Stride 4.5, it is an error again.

## Explanation

A method with the name and the parameters of an inherited **abstract** method implements it only when it is marked `override`. Without `override`, the code doesn't say what it does: the compiler stops with this error instead of guessing.

When the inherited method has a body, the same mistake is the error SDSL0115: without `override`, the method would start a separate method, and calls through the parent wouldn't reach it.

## Example

The following example generates SDSL0114 in `MyInvert`:

```cs
shader MyFilterBase
{
    import ImageEffectShader;
    import Texturing;

    abstract float4 Filter(float4 color);

    module override float4 Shading()
    {
        return Filter(Texture0.Sample(LinearSampler, streams.TexCoord));
    }
};

[Root]
shader MyInvert : MyFilterBase
{
    float4 Filter(float4 color) { return float4(1 - color.rgb, color.a); }
};
```

The following example doesn't generate SDSL0114:

```cs
[Root]
shader MyInvert : MyFilterBase
{
    override float4 Filter(float4 color) { return float4(1 - color.rgb, color.a); }
};
```

## Solution

Add the `override` keyword. The project upgrade to Stride 4.5 adds it for you.
