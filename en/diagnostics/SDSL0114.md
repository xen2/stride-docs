# Diagnostics Warning SDSL0114

> {0}.{1}({2}) at line {3} implements abstract method {4}.{1} but is not marked 'override'; it is compiled as an override. Add the 'override' keyword.

Reported by the shader compiler since Stride 4.4 (an error in the first 4.4 versions, a warning since the fix that compiles the method as an override).

## Explanation

A method with the name and the parameters of an inherited **abstract** method implements it. The compiler links it to the abstract method like an `override`, so calls through the parent reach it, and reports this warning: write `override` so the code says what it does.

When the inherited method has a body, the same mistake is the error SDSL0115: without `override`, the method would start a separate method, and calls through the parent wouldn't reach it.

## Example

The following example generates SDSL0114 in `MyInvert`:

```cs
shader MyFilterBase
{
    import ImageEffectShader;
    import Texturing;

    abstract float4 Filter(float4 color);

    module override float4 Shading()
    {
        return Filter(Texture0.Sample(LinearSampler, streams.TexCoord));
    }
};

[Root]
shader MyInvert : MyFilterBase
{
    float4 Filter(float4 color) { return float4(1 - color.rgb, color.a); }
};
```

The following example doesn't generate SDSL0114:

```cs
[Root]
shader MyInvert : MyFilterBase
{
    override float4 Filter(float4 color) { return float4(1 - color.rgb, color.a); }
};
```

## Solution

Add the `override` keyword. The project upgrade adds it for the abstract methods of your project's shaders.

To make this warning fail the build, set the MSBuild property `StrideShaderWarningsAsErrors` to `true` in your project.
