# Diagnostics Warning SDSL0216

> {0} is written for an older Stride version ({1}); it was upgraded when it was loaded. Update the source: ShaderUpgrader.UpgradeSource gives the new text.

Reported by the shader compiler since Stride 4.5.

## Explanation

The project upgrade rewrites the `.sdsl` files of your project when you open it with a new Stride version. Some shader sources never go through it, because the asset pipeline doesn't import them:

- `.sdsl` files that a tool reads from the disk at run time (for example the shader folders of vvvv);
- shader code that a tool or a library generates and registers at run time with `ShaderSourceManager.AddShaderSource`.

When such a source uses syntax from before Stride 4.5, the shader compiler upgrades it in memory when it loads it, with the same steps as the project upgrade, and reports this warning once for the source. `{1}` lists the steps that changed the text (for example `stage-to-module`: `stage` is now `module`). The rest of the message says what else the upgrade did or couldn't do.

The upgrade of one source knows only that source, the classes it inherits or uses by name, and the engine. So it never turns a class of the source into a module: only the project upgrade, which sees every file, can know that no class has instances of it.

## Example

This source, registered at run time, generates SDSL0216:

```cs
shader MyGeneratedValue : ComputeFloat
{
    stage float Scale;

    override float Compute()
    {
        return Scale;
    }
};
```

This one doesn't:

```cs
shader MyGeneratedValue : ComputeFloat
{
    module float Scale;

    override float Compute()
    {
        return Scale;
    }
};
```

## Solution

Update the source, then the warning goes away:

- For a file, run the upgrade on it: `ShaderUpgrader.UpgradeSource(path, text)` in `Stride.Shaders.Parsers` returns the new text. To upgrade a whole shader library at once, use `ShaderUpgrader.Upgrade(files, EngineShaderClasses.Current)`.
- For generated code, change the generator so that it writes the 4.5 syntax.

The asset pipeline's sources are never upgraded this way: a project shader with old syntax gets the compile errors, with their fix in [Upgrading shaders from 4.4](../release-notes/upgrading-shaders-4.5.md). A tool can turn the upgrade at load off with `ShaderSourceManager.UpgradeSources = false`.
