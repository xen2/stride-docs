# Diagnostics Warning SDSL0216

> {0}.{1} doesn't call base, so {2} never run in this effect. Call base to keep them.

Reported by the shader compiler since Stride 4.5, for an effect built by the asset compiler. In a mix built at run time, the same text goes to the log as information.

## Explanation

An [extension point](../manual/graphics/effects-and-shaders/shading-language/extension-points.md) chains its overrides. An override that doesn't call `base` stops the chain there, so the overrides before it never run. That can be what you want, but nothing else in the source says so, and an engine feature can stop working without any other message.

The first definition doesn't count: replacing the default body is what an override is for. Replacing what one of your own parents contributed is normal inheritance and isn't reported either. An `import` is not a parent.

## Example

The following example generates SDSL0216 when `MyStep` and `MyReplacement` are mixed in one effect:

```cs
module MyModule
{
    stream float Value;

    [Pipeline]
    void Run() {}
};

module MyStep
{
    import MyModule;

    override void Run() { base.Run(); streams.Value = 1; }
};

module MyReplacement
{
    import MyModule;

    override void Run() { streams.Value = 2; }
};
```

The following example doesn't generate SDSL0216:

```cs
module MyReplacement
{
    import MyModule;

    override void Run() { base.Run(); streams.Value = 2; }
};
```

## Solution

Call `base` to keep the other overrides. To drop them on purpose, keep the code as it is: the warning stays until a later version of SDSL lets the override say so.
