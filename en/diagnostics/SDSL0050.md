# Diagnostics Error SDSL0050

> {0} {1} is declared inside {2} {3}, but it is not a member of a {2}. Move it out of the block

Reported when your project builds, since Stride 4.5.

## Explanation

A `cbuffer` block holds values the CPU sets, and an `rgroup` block holds resources (textures, samplers, buffers). A composition (`compose`) or a stream (`stream`) is neither: it belongs to the shader itself. Stride 4.3 accepted one inside the block and moved it out silently; since Stride 4.4 it is an error, and this message says what to move.

## Example

The following example generates SDSL0050:

```cs
shader MyColor : ComputeColor
{
    rgroup PerMaterial
    {
        stage Texture2D ShrinkTexture;
        stage compose ComputeFloat ShrinkStrength;
    }

    override float4 Compute()
    {
        return ShrinkStrength.Compute();
    }
};
```

The following example doesn't generate SDSL0050:

```cs
shader MyColor : ComputeColor
{
    rgroup PerMaterial
    {
        stage Texture2D ShrinkTexture;
    }

    stage compose ComputeFloat ShrinkStrength;

    override float4 Compute()
    {
        return ShrinkStrength.Compute();
    }
};
```

## Solution

Move the `compose` or `stream` declaration out of the block, into the shader. The shader works as it did in Stride 4.3.
