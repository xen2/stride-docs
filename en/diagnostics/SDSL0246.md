# Diagnostics Warning SDSL0246

> {0} overrides {1} of {2}, which is not an extension point, so its place in the chain depends on the mix order. Add [Replace], [Pipeline] or [Around] to the first definition of {1}.

Reported by the shader compiler since Stride 4.5.

## Explanation

A `module` method has one chain of overrides per effect, and every class in the effect can add to it. An [extension point](../manual/graphics/effects-and-shaders/shading-language/extension-points.md) says how they combine. Without a kind, nothing says it: the override still works, but its result depends on what else is mixed, and in which order.

All the engine methods that are meant to be overridden are extension points. So this warning means that the method belongs to your code or to a library, or that it is an engine method not meant for overriding, which can change without notice.

Implementing an `abstract` method and overriding an instance method don't report it.

## Example

The following example generates SDSL0246:

```cs
module MyModule
{
    float Factor() { return 1; }
};

module MyOverride
{
    import MyModule;

    override float Factor() { return 2; }
};
```

The following example doesn't generate SDSL0246:

```cs
module MyModule
{
    [Replace]
    float Factor() { return 1; }
};
```

## Solution

If the method is yours or your library's, add the kind that says what its overrides do. If it is an engine method, ask for it to become an extension point, or keep the override and expect to check it after an upgrade.

To make this warning fail the build, set the MSBuild property `StrideShaderWarningsAsErrors` to `true` in your project.
