# Diagnostics Error SDSL0246

> {0} overrides {1} of {2}, which is not an extension point. The first definition of {1} in {2} has to say how its overrides combine: add [Replace], [Pipeline] or [Around] to it. If {2} is in a library or in the engine, its author has to add it.

Reported by the shader compiler since Stride 4.5.

## Explanation

A `module` method has one chain of overrides per effect, and every class in the effect can add to it. An [extension point](../manual/graphics/effects-and-shaders/shading-language/extension-points.md) says how they combine. An override of a `module` method whose first definition doesn't say it doesn't compile.

Implementing an `abstract` method and overriding an instance method don't report it.

## Example

The following example generates SDSL0246:

```cs
module MyModule
{
    float Factor() { return 1; }
};

module MyOverride
{
    import MyModule;

    override float Factor() { return 2; }
};
```

The following example doesn't generate SDSL0246:

```cs
module MyModule
{
    [Replace]
    float Factor() { return 1; }
};
```

## Solution

Upgrading a project adds the kind for you when the first definition is in the project: `[Pipeline]` if an override calls `base`, else `[Replace]`. You can also write it by hand, with the kind that says what the overrides do.

If the first definition is in a library or in the engine, its author has to add the kind. Until then, you can write [`patch`](../manual/graphics/effects-and-shaders/shading-language/extension-points.md#extend-a-method), which says that you change a method that wasn't meant to change.
