# Diagnostics Error SDSL0163

> The call {0} is ambiguous: these overloads match equally well:{1}
> Cast the arguments to the parameter types of the one to call.

Reported when your project builds, since Stride 4.5.

## Explanation

Several overloads can take the arguments, and none of them is a better match. The shader compiler ranks overloads like the HLSL compiler (DXC):

- Each argument counts the conversions it needs. From the mildest to the worst: a scalar that fills a vector (`1` to `float3`), a promotion (`half` to `float`, `float` to `double`), a sign change (`int` to `uint`), another element conversion (`int` to `float`, `float` to `int`), a truncation (`float4` to `float3`).
- One conversion of a worse kind weighs more than any number of milder ones. With `Map(float, float, float)` and `Map(float2, float2, float2)`, the call `Map(uv, 0, 1)` with a `float2 uv` takes the `float2` overload: two scalars fill vectors, which is better than one truncation of `uv`.
- For the same kind, the overload with fewer conversions wins. If the counts are the same too, the call is ambiguous. This includes truncations of different sizes: `float3` to `float` and `float3` to `float2` are both one truncation.

## Example

The following example generates SDSL0163:

```cs
shader MyMix : ComputeColor
{
    float Mix(float a, int b) { return a * b; }
    float Mix(int a, float b) { return a + b; }

    override float4 Compute()
    {
        float x = 0.5;
        return Mix(x, x);
    }
};
```

The following example doesn't generate SDSL0163:

```cs
shader MyMix : ComputeColor
{
    float Mix(float a, int b) { return a * b; }
    float Mix(int a, float b) { return a + b; }

    override float4 Compute()
    {
        float x = 0.5;
        return Mix(x, (int)x);
    }
};
```

## Solution

Cast the arguments to the parameter types of the overload you want, or rename one of the overloads.
