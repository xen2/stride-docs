# Diagnostics Error SDSL0141

> [Phase({0})] on {1}: {2}.

Reported by the shader compiler since Stride 4.5, when a class compiles, and when an effect is mixed for a phase with a dot in its name.

## Explanation

`[Phase]` places an override in a phase of an [extension point](../manual/graphics/effects-and-shaders/shading-language/extension-points.md). The message says what is wrong:

- the first definition doesn't declare this phase, and the message lists the ones it declares;
- the phase has a dot in its name, so another class can add it, and no class of the effect does. The compiler checks this when it mixes the effect, also for a phase that a [block](../manual/graphics/effects-and-shaders/effect-language.md#blocks) of the effect names;
- the method is not an extension point, so it has no phases;
- `[Phase]` is on a method that overrides nothing.

## Example

The following example generates SDSL0141:

```cs
module MyModule
{
    [Phases(First, Second)]
    pipeline void Run() {}
};

module MyStep
{
    import MyModule;

    [Phase(Third)]
    override void Run() { base.Run(); }
};
```

The following example doesn't generate SDSL0141:

```cs
module MyStep
{
    import MyModule;

    [Phase(Second)]
    override void Run() { base.Run(); }
};
```

## Solution

Use a phase that the first definition declares, or remove `[Phase]`: an override without a phase runs outside every phase, in the order of the mixins. For a phase that another class adds, mix that class in the effect too.
