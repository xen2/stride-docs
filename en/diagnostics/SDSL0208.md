# Diagnostics Warning SDSL0208

> base.{1}() in {0}.{2}(): {1} is a module method, called from instance code. If {0} is used in a composition, the call fails. Make {2} 'module' ('override module' if it is an override), or mark {0} [Root] if it is only mixed at the root of an effect.

Reported by the shader compiler since Stride 4.5.

## Explanation

`base.X()` calls the previous method of the same override chain. A module method's chain exists once per effect, in the root of the effect; instance code (a method without `module`) is in each composition's own node. So instance code can't call a module method through `base`. When the shader is used in a composition, the effect fails to build.

This usually comes with [SDSL0206](SDSL0206.md): a plain `override` of a module method that calls `base`.

The compiler checks this when the class compiles, unless the class is root-only (see [SDSL0119](SDSL0119.md)).

## Example

The following example generates SDSL0208 (and SDSL0206) in `PreTransformPosition`:

```cs
shader MyWind
{
    import TransformationBase;
    import PositionStream4;

    override void PreTransformPosition()
    {
        base.PreTransformPosition();
        streams.Position.x += sin(Global.Time) * 0.1;
    }
};
```

The following example doesn't generate SDSL0208:

```cs
shader MyWind
{
    import TransformationBase;
    import PositionStream4;

    module override void PreTransformPosition()
    {
        base.PreTransformPosition();
        streams.Position.x += sin(Global.Time) * 0.1;
    }
};
```

## Solution

Make the calling method `module` (write `override module` when it is an override). If the shader is only mixed at the root of an effect, you can mark it `[Root]` instead.

To make this warning fail the build (it will be an error in a later release), set the MSBuild property `StrideShaderWarningsAsErrors` to `true` in your project.
