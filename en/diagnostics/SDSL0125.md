# Diagnostics Error SDSL0125

> {0} {1} has type {2}, which is or contains the partial struct {3}. The fields of a partial struct depend on the effect, so it can't be in streams, cbuffers, buffers or groupshared variables. Use a plain struct there.

Reported by the shader compiler since Stride 4.5.

## Explanation

The fields of a [partial struct](../manual/graphics/effects-and-shaders/shading-language/automatic-shader-stage-input-output.md#partial-structs) depend on which classes the effect uses. Some places need a layout that is the same for C#, for another shader stage or for another effect, so they can't hold a partial struct:

- streams (stage inputs and outputs),
- cbuffer members, and shader members that are not `static` (they go into a cbuffer),
- buffer elements (`StructuredBuffer<T>` and the other buffer types),
- `groupshared` variables.

This is also true for a plain struct, or an array, that contains a partial struct.

A partial struct can be used for local variables, parameters, return values and `static` variables.

## Example

The following example generates SDSL0125:

```cs
module MySurface
{
    partial struct MySurfaceInput
    {
        float3 normalWS;
    };
};

shader MyShading
{
    import MySurface;

    stream MySurfaceInput surface;
};
```

The following example doesn't generate SDSL0125:

```cs
module MySurface
{
    partial struct MySurfaceInput
    {
        float3 normalWS;
    };
};

shader MyShading
{
    import MySurface;

    stream float3 normalWS;

    MySurfaceInput GetSurface()
    {
        MySurfaceInput surface = (MySurfaceInput)0;
        surface.normalWS = streams.normalWS;
        return surface;
    }
};
```

## Solution

Keep the partial struct in local variables and parameters. Where the data crosses a stage, a cbuffer or a buffer, use plain fields or a plain struct, and copy the values into the partial struct where it is used.
