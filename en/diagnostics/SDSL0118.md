# Diagnostics Error SDSL0118

> {0} declares generic parameter '{1}' of type {2} at line {3}. Texture and sampler generic parameters are not supported. Declare a texture or sampler member instead, or use a ComputeColorTexture...Sampler shader with a texture key.

Reported by the shader compiler since Stride 4.5. In Stride 4.4, the same shader compiled, but the effect that used it failed with the message "The method or operation is not implemented".

## Explanation

A generic parameter is a value that is fixed when the effect is compiled: a number, a semantic, or a name (`LinkType`, `MemberName`). A texture or a sampler isn't such a value: it's a resource that the engine binds at run time. So a generic parameter can't have a texture type (`Texture2D`, `TextureCube`, ...) or a sampler type (`SamplerState`, `SamplerComparisonState`).

## Example

The following example generates SDSL0118:

```cs
shader MyTextureColor<Texture2D TTexture, Semantic TStream> : ComputeColor
{
    stream float2 TexCoord : TStream;

    SamplerState MySampler;

    override float4 Compute()
    {
        return TTexture.Sample(MySampler, streams.TexCoord);
    }
};
```

The following example doesn't generate SDSL0118:

```cs
shader MyTextureColor<Semantic TStream> : ComputeColor
{
    stream float2 TexCoord : TStream;

    Texture2D MyTexture;
    SamplerState MySampler;

    override float4 Compute()
    {
        return MyTexture.Sample(MySampler, streams.TexCoord);
    }
};
```

## Solution

Declare the texture or the sampler as a member of the shader. The engine creates a parameter key for it (here `MyTextureColorKeys.MyTexture`), and you set the texture with that key.

To choose the texture by name when the shader is used, use a `LinkType` generic parameter, like the engine's `ComputeColorTextureSampler` shaders. In a material, use the **Texture** node: it generates these shaders for you.

Typed texture handles, which will let a shader take a texture as a parameter, are planned for a later release.
