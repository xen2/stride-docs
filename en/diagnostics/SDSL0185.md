# Diagnostics Error SDSL0185

> {0} works on an int or uint, but its destination {1} has type {2}. Use an int or uint element of a buffer, a texture or a groupshared variable (for a float, store its bits with asuint and update it with InterlockedCompareExchange).

Reported when your project builds, since Stride 4.5.

## Explanation

The `Interlocked*` intrinsics (`InterlockedAdd`, `InterlockedMin`, `InterlockedCompareExchange`...) change one 32-bit integer: their first argument must be an `int` or a `uint`. A `float`, a vector or a swizzle of several components can't be the destination, as in HLSL.

## Example

The following example generates SDSL0185:

```cs
shader Histogram : ComputeShaderBase
{
    RWStructuredBuffer<float> Total;

    override void Compute()
    {
        InterlockedAdd(Total[0], 1);
    }
};
```

The following example doesn't generate SDSL0185:

```cs
shader Histogram : ComputeShaderBase
{
    RWStructuredBuffer<uint> Total;

    override void Compute()
    {
        InterlockedAdd(Total[0], 1);
    }
};
```

## Solution

Declare the buffer (or the struct member, or the groupshared variable) as `int` or `uint`. To add to a `float`, keep its bits in a `uint` and retry until no other thread changed it:

```cs
uint expected, original;
do
{
    expected = Total[0];
    InterlockedCompareExchange(Total[0], expected, asuint(asfloat(expected) + value), original);
} while (original != expected);
```
