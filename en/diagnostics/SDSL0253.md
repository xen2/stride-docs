# Diagnostics Error SDSL0253

> phase {0}, added by {1}: a name that starts with Stride. is kept for the engine. Give the phase a prefix of your own.

Reported by the shader compiler since Stride 4.5, and when an effect project builds for a phase that a block adds.

## Explanation

The phases that classes of the engine add start with `Stride.`, so that a project or a library never takes one of their names. The compiler can't see which assembly a class comes from, so it checks the namespace of the class that adds the phase: a class outside the `Stride` namespaces can't add a phase that starts with `Stride.`. A block of an effect adds a phase for its class, so the same applies to it.

## Example

The following example generates SDSL0253:

```cs
namespace MyGame;

module MyStep
{
    import ShaderBase;

    [Phase(Stride.Wind, After = Input)]
    extend ShaderBase.PSMain() { ... }
};
```

The following example doesn't generate SDSL0253:

```cs
namespace MyGame;

module MyStep
{
    import ShaderBase;

    [Phase(MyGame.Wind, After = Input)]
    extend ShaderBase.PSMain() { ... }
};
```

## Solution

Use a prefix of your own. To join a phase the engine adds, `[Phase(Stride.Name)]` without neighbours is fine.
