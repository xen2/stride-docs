# Diagnostics Error SDSL0181

> Buffer parameter '{0}' of {1} is '{2}': a buffer parameter always refers to the caller's buffer, so it can't be out or inout. Remove '{2}'.

Reported when your project builds, since Stride 4.5.

## Explanation

A method can take a structured buffer or a byte address buffer as a parameter. The method then reads and writes the buffer that the caller gives: a `RWStructuredBuffer` or `RWByteAddressBuffer` parameter is enough to write into it.

The parameter can't be `out` or `inout`, because a method can't give the caller another buffer. Each call must give a buffer declared in a shader (or a buffer parameter of the calling method), so that the compiler knows which buffer the call uses.

## Example

The following example generates SDSL0181:

```cs
shader Particles : ComputeShaderBase
{
    void Reset(out RWStructuredBuffer<float4> target, uint index)
    {
        target[index] = 0;
    }
};
```

The following example doesn't generate SDSL0181:

```cs
shader Particles : ComputeShaderBase
{
    void Reset(RWStructuredBuffer<float4> target, uint index)
    {
        target[index] = 0;
    }
};
```

## Solution

Remove `out` or `inout`. To write into the buffer, give the parameter a read-write type (`RWStructuredBuffer` or `RWByteAddressBuffer`).
