# Diagnostics Error SDSL0195

> {0} holds an int, uint or bool matrix ({1}), which can't be in a cbuffer or a buffer yet. Use an array of {2} instead, or a float matrix; a static matrix (or a local one) works.

Reported when your project builds, since Stride 4.5.

## Explanation

SPIR-V has floating-point matrices only. Like DXC, Stride compiles an `int`, `uint` or `bool` matrix (`int4x4`, `uint3x3`, `bool2x2`...) as an array of its rows. That works for local variables, `static` and `static const` members, parameters and struct members of local values.

In a constant buffer (any member that isn't `static`), or in a structured buffer element, the array would need the matrix's memory layout, which Stride doesn't provide yet.

## Example

The following example generates SDSL0195:

```cs
shader Sharpen : ComputeShaderBase
{
    int3x3 Kernel;
    RWStructuredBuffer<int> Output;

    override void Compute()
    {
        Output[0] = Kernel[1][1];
    }
};
```

The following example doesn't generate SDSL0195:

```cs
shader Sharpen : ComputeShaderBase
{
    int3 Kernel[3];
    RWStructuredBuffer<int> Output;

    override void Compute()
    {
        Output[0] = Kernel[1][1];
    }
};
```

## Solution

Declare the member as an array of rows (`int3 Kernel[3]` for an `int3x3`): `Kernel[row][column]` reads it the same way. If the values never change, make the matrix `static const`. A float matrix works too, if its values fit.
